# منصة نواتج التعلم — مدرسة أبوداوود الابتدائية

منصة كاملة (واجهة + قاعدة بيانات سحابية) جاهزة للرفع على **Cloudflare Pages** مع **Cloudflare D1**.
**لا يوجد أي تخزين للبيانات المدرسية (طلاب/معلمين/نتائج) في متصفح الجهاز.** كل البيانات تُقرأ وتُكتب مباشرة من قاعدة بيانات D1 السحابية عبر واجهة API، بحيث يرى المعلم والمشرف نتيجة أي طالب فور حفظها، من أي جهاز. العنصر الوحيد المحفوظ في المتصفح هو رمز جلسة الدخول (token) لتفادي إعادة تسجيل الدخول عند تحديث الصفحة — وهذا لا يحتوي على أي بيانات مدرسية.

## خطوات الرفع (بدون سطر أوامر — عبر لوحة Cloudflare مباشرة)

### 1) رفع الملفات (Direct Upload)
من لوحة Cloudflare: **Workers & Pages ← Create ← Pages ← Upload assets**.
اسحب وأفلت **كل الملفات التالية فقط** (وليس مجلدًا مضغوطًا):
`index.html`, `app.js`, `styles.css`, `_worker.js`, `schema.sql`, `seed.sql`, `README.md`

**لا ترفع `wrangler.toml`** — احذفه من قائمة الرفع (زر ⊗ بجانبه) قبل الضغط على Deploy، فالرفع المباشر من المتصفح لا يدعم ملفات إعداد Wrangler ويوقف العملية برسالة خطأ. هذا الملف مخصص فقط لمن ينشر عبر سطر الأوامر (Wrangler CLI) من جهازه.

اضغط **Deploy site**.

> **ملاحظة مهمة:** الكود الخلفي (API) موجود في ملف واحد باسم `_worker.js` في الجذر (وليس داخل مجلد `functions/`)، لأن الرفع المباشر من لوحة Cloudflare **لا يدعم مجلد `functions/` إطلاقًا** (قيد معروف من Cloudflare نفسها). صيغة `_worker.js` هذه مدعومة بالكامل من الرفع المباشر، وتقوم تلقائيًا بخدمة الملفات الثابتة (`index.html`, `app.js`, `styles.css`) بالإضافة لتشغيل واجهة الـ API — بنفس الوظائف تمامًا.

### 2) إنشاء قاعدة بيانات D1
من نفس لوحة Cloudflare: **Storage & Databases ← D1 SQL Database ← Create Database**، وسمّها مثلاً `nawatej-db`.

### 3) تنفيذ الجداول والبيانات الأولية
من صفحة قاعدة البيانات التي أنشأتها، هناك تبويب **Console** (أو "وحدة التحكم") يتيح تنفيذ استعلامات SQL مباشرة من المتصفح:
- افتح `schema.sql` من الملفات، انسخ محتواه بالكامل، الصقه في الـ Console ونفّذه (Execute/Run).
- كرر نفس الشيء مع `seed.sql` (ملف كبير، امنحه وقتًا لينفّذ). هذا يزرع تلقائيًا: توزيع المنهج، بنك الأسئلة (400 سؤال)، **342 طالبًا** (الثالث 113 طالبًا في 3 فصول، السادس 229 طالبًا في 7 فصول)، وحساب المشرف الافتراضي.

بديل أسرع إن كنت تفضّل سطر الأوامر لهذه الخطوة تحديدًا:
```
wrangler d1 execute nawatej-db --remote --file=./schema.sql
wrangler d1 execute nawatej-db --remote --file=./seed.sql
```

### 4) ربط قاعدة البيانات بمشروع Pages
ارجع لمشروع Pages الذي أنشأته ← **Settings ← Bindings (أو Functions) ← D1 database bindings ← Add binding**:
- **Variable name:** `DB` (بالضبط، بأحرف كبيرة)
- **D1 database:** اختر `nawatej-db`

احفظ، ثم أعد نشر آخر إصدار (Retry deployment) حتى يسري الربط.

### 5) تأكد من عمل الموقع
افتح رابط الموقع (`اسم-مشروعك.pages.dev`) وجرّب الدخول ببيانات المشرف الافتراضية أدناه.

## بيانات دخول المشرف الافتراضية
- اسم المستخدم: `admin`
- كلمة المرور: `Nawatej@1448`

**غيّرها فور أول دخول** من: إعدادات الاختبارات ← بيانات دخول المشرف.

## قائمة الطلاب
تم استيراد **342 طالبًا** من ملفي إكسل المرفوعين، مصنّفين تلقائيًا في `seed.sql`:
- **الصف الثالث:** 113 طالبًا في 3 فصول (3/1، 3/2، 3/3).
- **الصف السادس:** 229 طالبًا في 7 فصول (6/1 إلى 6/7).

المشرف يستطيع لاحقًا إضافة/تعديل/نقل/حذف أي طالب من "إدارة الطلاب"، ويبقى السجل التاريخي محفوظًا في قاعدة البيانات (حذف الطالب يُخفيه من القوائم فقط، دون حذف نتائجه).

**تنبيه لـ 6 طلاب:** أرقام هوياتهم في ملف الإكسل الأصلي كانت 9 خانات فقط بدل 10، فتم إكمالها بصفر في البداية افتراضيًا داخل `seed.sql`. تأكد من صحتها قبل الاعتماد النهائي:
- محمود احمد عمر حريب (ثالث/1): 0150769243
- فهد بن فيصل بن بدر الهاجري (ثالث/3): 0140730210
- زايد عايض زايد العجمي (سادس/2): 0110509002
- صالح سعيد منصور العجمي (سادس/4): 0111070771
- عبدالرحمن رائد يوسف الياسي (سادس/6): 0150607326
- محمد ماجد عبدالله الشيباني (سادس/7): 0170259274

## إضافة المعلمين (للمشرف)
من "المعلمون" ← "+ إضافة معلم"، أدخل: الاسم، اسم مستخدم فريد (هذا ما يدخل به المعلم لاحقًا)، المادة، الصف، الفصول (مفصولة بفاصلة مثل `3/1, 3/2`)، وكلمة مرور. كلمة المرور تُخزَّن على الخادم بصيغة مُجزّأة (PBKDF2-SHA256 + ملح عشوائي) وليست نصًا صريحًا أبدًا. يرى المعلم بعد الدخول طلاب فصوله المسندة فقط.

## نظام الاختبار الأسبوعي
- بنك الأسئلة (400 سؤال) مصنّف حسب الصف/المادة/**الأسبوع** تبعًا لتوزيع المنهج، ومخزّن بالكامل في D1.
- **الإجابة الصحيحة لا تُرسل للمتصفح أبدًا** قبل تسليم الطالب إجاباته — التصحيح يتم على الخادم فقط، فلا يمكن لأي طالب معرفة الإجابات من كود الصفحة.
- تُفتح المنصة للطالب **يومين فقط في الأسبوع** (افتراضيًا الأحد والأربعاء، قابلة للتغيير من "إعدادات الاختبارات"). حساب اليوم والأسبوع يعتمد على توقيت الرياض (UTC+3) وليس توقيت الخادم.
- في يوم الاختبار، يحل الطالب أسئلة **الأسبوع الحالي فقط** لكل مواده — لغتي ورياضيات للثالث، وتُضاف علوم للسادس.
- بعد الإرسال تظهر **النتيجة فورًا** مع **عبارة حماسية** تتدرّج حسب الأداء، ولا يمكن إعادة حل اختبار الأسبوع نفسه مرتين.

## متابعة المتعثرين (للمعلم والمشرف)
تظهر تلقائيًا في الصفحة الرئيسية بطاقة **"🔴 طلاب بحاجة إلى متابعة"** لكل طالب نسبة إجاباته الصحيحة أقل من 50٪ (بعد 4 إجابات على الأقل)، مع عمود "الحالة" (🟢 متقن / 🔴 متعثر / 🟡 لم يشارك) في التقارير — محسوبة مباشرة من قاعدة البيانات فور كل إجابة.

## الأمان
- كل كلمات المرور (معلمين ومشرف) مُجزّأة على الخادم (PBKDF2-SHA256، 20000 تكرار، ملح عشوائي لكل حساب) — لا يوجد نص صريح لأي كلمة مرور في أي مكان.
- تسجيل الدخول يُنشئ رمز جلسة صالحًا 12 ساعة فقط، ويُطلب في كل طلب عبر ترويسة `Authorization`.
- نطاق كل معلم مقيّد فعليًا على الخادم (وليس فقط في الواجهة) بصفّه وفصوله ومادته — حتى لو حاول الوصول مباشرة عبر API لن يرى بيانات خارج نطاقه.

## هيكل الملفات
- `index.html`, `styles.css`, `app.js` — الواجهة.
- `_worker.js` — واجهة الـ API الكاملة (تعمل كملف Worker واحد يخدم الـ API والملفات الثابتة معًا؛ هذه الصيغة مدعومة من "الرفع المباشر" في لوحة Cloudflare، على عكس مجلد `functions/`).
- `schema.sql` — بنية قاعدة بيانات D1.
- `seed.sql` — البيانات الأولية: المنهج، بنك الأسئلة، الطلاب الـ342، حساب المشرف الافتراضي.
- `wrangler.toml` — **لا يُرفع مع باقي الملفات عند استخدام الرفع المباشر**؛ مفيد فقط إن نشرت لاحقًا عبر Wrangler CLI.
